# G2D integration guide

How to put the G2D 2D / 2.5D GPU into a system-on-chip or an FPGA design. G2D is one IP block: a configuration
slave port, one AXI4 memory master and an interrupt. It renders into frame buffers in memory; showing them on a
screen is the job of the SoC's display controller (G2D has none, like other GPU IPs of this class).

Reference material: `spec/arch.md` (architecture, ports, parameters), `docs/regs.md` (register map, generated from
`spec/regs.yaml`), `spec/commands.md` (command format), `spec/rendering.md` (bit-exact rendering rules).
Software: `sw/driver/vg_lite` implements the VGLite API on G2D through a small HAL (`sw/driver/hal`).

## 1. Choosing the top level

| Top | Configuration port | Use |
|---|---|---|
| `g2d_top` | AXI4-Lite slave, 32-bit (`s_axil_*`) | AXI systems with an AXI4-Lite peripheral bus |
| `g2d_top_axi` | AXI4 slave, data 32..512 bit, any ID width (`s_axi_*`) | directly on an AXI4 interconnect |
| `g2d_top_apb` | APB3 / APB4 (`s_apb_*`) | Arm peripheral buses |
| `g2d_top_ahb` | AHB-Lite subordinate (`s_ahb_*`) | Cortex-M class systems |
| `g2d_top_obi` | OBI 1.x subordinate (`s_obi_*`) | OpenHW / CORE-V systems |
| `g2d_top_regintf` | PULP reg_intf (`s_reg_*`) | PULP register buses |
| `g2d_top_wb` | Wishbone B4 pipelined (`s_wb_*`) | Wishbone SoCs |
| `g2d_top_tlul` | TileLink-UL (`s_tl_*`) | OpenTitan / Chipyard style systems |

The `g2d_top_<bus>` wrappers are generated by `make regs` (`scripts/gen_wrappers.py`) into `rtl/wrap/generated/`
(committed; regenerate after changing `g2d_top` or an adapter).
Each one is `g2d_top` with the adapter `rtl/adapt/g2d_<bus>2axil.sv` in front of its configuration port; all other
ports and parameters are `g2d_top`'s. Adapter parameters appear as `CFG_*` (AXI4: `CFG_DATA_W`, `CFG_ADDR_W`,
`CFG_ID_W`; TL-UL: `CFG_SRC_W`, `CFG_SIZE_W`).

Configuration-port behaviour common to all adapters:
- one access at a time, every access is a 32-bit register access, byte strobes are passed through;
- only the low 12 address bits are decoded (4 KB window); place the window anywhere in the address map;
- an access to an unmapped offset gets an error response on the bus (SLVERR / PSLVERR / HRESP / err / d_error);
- the AXI4 adapter splits bursts into word accesses (INCR, FIXED, WRAP, narrow and unaligned transfers), reflects
  IDs, answers exclusive accesses OKAY (= exclusive failed) and does not implement AXI5 atomics: put an atomics
  filter in front if the interconnect can issue them (the Cheshire integration uses PULP's `axi_atop_filter`);
- the AHB-Lite adapter answers transfers wider than 32 bits or unaligned with the two-cycle ERROR response; its
  `s_ahb_hready_i` is the bus HREADY (in a single-subordinate system, connect it to `s_ahb_hreadyout_o`);
- the TL-UL adapter accepts PutFullData, PutPartialData and Get; other opcodes get `d_error`;
- the Wishbone adapter drops the response of an access whose cycle was ended early (`cyc` low).

## 2. Parameters

The full list is `spec/arch.md` §3. The ones an integrator normally sets:

| Parameter | Default | Notes |
|---|---|---|
| `DATA_W` | 64 | memory port data width, 64 or 128 |
| `ADDR_W` | 32 | memory address width, 32..64; bits above 31 come from CSR `MEM_BASE_HI` |
| `ID_W` | 4 | memory port ID width, at least 3 |
| `RD_OUTSTANDING`, `WR_OUTSTANDING` | 16, 8 | bursts in flight; must not exceed what the interconnect accepts |
| `MAX_BURST_BYTES` | 256 | longest burst, 64..4096 |
| `CFG_ASYNC`, `MEM_ASYNC` | 0 | put the configuration / memory port on its own clock (§3) |
| `FEATURES` | all | leave out optional units to save area (`spec/arch.md` §3; the driver adapts via `HWCFG`) |
| `IRQ_PULSE`, `IRQ_ACTIVE_LOW` | 0, 0 | interrupt style (§5) |
| `RST_STAGES` | 2 | core reset distribution stages |

## 3. Clocks, resets and constraints

- **Clocks.** `clk_i` is the core clock. With `CFG_ASYNC = 0` / `MEM_ASYNC = 0` the port runs on `clk_i` and
  `clk_cfg_i` / `clk_mem_i` are unused (tie them to `clk_i`). With `= 1` the port has its own clock and an internal
  clock-domain crossing (gray-coded FIFOs, `spec/arch.md` §2.1). The configuration-bus adapters of the wrappers sit
  in the configuration-port domain.
- **Resets.** Active low, asserted asynchronously, released synchronously to their own clock: the integrator's
  reset synchronizer drives `rst_ni`, `rst_cfg_ni`, `rst_mem_ni`. With a crossing, assert all three together
  (`spec/arch.md` §2.2).
- **`test_mode_i`.** Tie to 0. In scan test mode, 1 makes the core reset follow `rst_ni` directly (the internal
  reset distribution flops are bypassed).
- **Constraints.** `syn/constraints/g2d_top.sdc` is a standard-SDC template: core clock (default 600 MHz),
  optional port clocks, input / output budgets as a fraction of the period, `test_mode_i` case analysis and the
  clock-domain-crossing bounds (maximum delay of the faster period, no hold check). Set the `G2D_*` variables at the
  top of the file before sourcing it. The FPGA build has its own Vivado form (`fpga/genesys2/g2d_cdc.tcl`).
  `scripts/check_sdc.py` checks that the template uses standard SDC only; `scripts/sta_sdc_check.py` reads it in
  OpenSTA against a port-only stub of `g2d_top` (all clock configurations); timing needs a synthesized netlist.

## 4. Memory port and quality of service

- AXI4 master, INCR bursts only, never across 4 KB, full-width beats, read ID = read client index, single write
  ID (`spec/arch.md` §4.2). Bursts in flight up to `RD_OUTSTANDING` / `WR_OUTSTANDING`.
- G2D expects normal memory (no side effects) for every buffer it reads or writes. `ADDR_WIN_LO` / `ADDR_WIN_HI`
  restrict every access to a window (a draw outside it is rejected before it starts).
- **Attributes** (CSR `MEM_ATTR`): AxCACHE, AxPROT, AxQOS per channel. Reset: AxCACHE = 0011 (normal
  non-cacheable bufferable), AxPROT = 0, AxQOS = 0. Set them for the system's coherency / security / QoS scheme.
  G2D is not cache-coherent: software cleans and invalidates CPU caches around GPU accesses (the driver's HAL).
- **Throttle** (CSR `MEM_QOS`, `spec/arch.md` §4.2.1): maximum read / write bursts outstanding and a minimum gap
  between burst requests per channel. Use it when the GPU must leave bandwidth to another master, e.g. a display
  controller that must not underrun. Off after reset.

## 5. Interrupt

`irq_o` is in the core clock domain. Default: active-high level, `|(IRQ_STATUS & IRQ_ENABLE)`. `IRQ_PULSE = 1`
gives a one-cycle pulse per newly pending enabled bit (at least one low cycle between pulses) for edge-triggered
controllers; `IRQ_ACTIVE_LOW = 1` inverts it. Synchronize it into the interrupt controller's clock domain if that
differs. Sources: fence with the IRQ flag, error, idle (`spec/arch.md` §7).

## 6. Memories

All on-chip memories go through two wrappers, `g2d_ram_1r1w` (one read, one write port) and `g2d_ram_sp` (single
port), about 45 KB in total (`spec/arch.md` §6.4). Pick one implementation per target by file list:

| Files | Target |
|---|---|
| `rtl/common/g2d_ram_1r1w.sv`, `g2d_ram_sp.sv` | behavioural (simulation, FPGA inference), default |
| `rtl/ram/xilinx/` | Xilinx: explicit block / distributed RAM selection by size |
| `rtl/ram/asic/` + a macro library | ASIC: wrappers mapped onto compiler-style macros `g2d_sram_2p` / `g2d_sram_1p` (active-low enables, bit-write mask) with a tied-off MBIST access path; `rtl/ram/asic/models/` holds behavioural stand-ins for simulation, to be replaced by the memory compiler's macros |

G2D never reads and writes the same address of a two-port RAM in the same cycle (the result would be undefined on
real macros); `DBG_STATUS.RAM_COLL` records it if it ever happens (`spec/arch.md` §9.1). The full GPU is
regression-tested with each variant (`dv/tests/test_ram_variants.py`).

## 7. Packaging

Generated by `make regs` (`scripts/gen_packaging.py`), committed, marked generated:

| File | Tool | Contents |
|---|---|---|
| `g2d.core` | FuseSoC (CAPI2) | core `::g2d:<regs version>`; targets `default` (behavioural RAMs), `xilinx`, `asic` (with the SDC), `lint` (Verilator) |
| `Bender.yml` | Bender | package `g2d`; targets: default behavioural RAMs, `xilinx`, `asic` |
| `ipxact/g2d_top.xml` | IP-XACT (IEEE 1685-2014) | component with the register map, the ports of `g2d_top` at the default parameters and the file set |

All three need the generated RTL first (`make regs`). FuseSoC: `fusesoc --cores-root <repo> run --target lint
::g2d:0.4.0`. Bender: `bender script flist -t asic`. The IP-XACT file has been checked against `spec/regs.yaml` and
validates against the IEEE 1685-2014 schema (`scripts/fetch_ipxact_schema.sh`, `docs/OPEN_QUESTIONS.md` Q-INT-3).

## 8. Bring-up checklist

1. Read `ID` (0x47324420, "G2D ") and `VERSION`; `HWCFG` shows the data width, address width, kick depth, crossings
   and built features.
2. Write `SCRATCH` and read it back (configuration path).
3. Set `ADDR_WIN_LO` / `ADDR_WIN_HI` to the memory the GPU may use, `MEM_BASE_HI` if `ADDR_W > 32`, and
   `MEM_ATTR` / `MEM_QOS` if the defaults do not fit.
4. Enable interrupts (`IRQ_ENABLE`) and check one with a fence that has the IRQ flag.
5. Run a clear into a frame buffer and compare it with the software renderer (the golden model is also the software
   fallback renderer, `model/`).
6. `PERF_*` counters give busy cycles and memory beats per draw; `DBG_STATUS` / `WR_SIG` help compare a board run
   with simulation (`spec/arch.md` §9.1).
